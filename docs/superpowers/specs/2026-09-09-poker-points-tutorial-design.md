# 德州扑克积分桌入门教程：设计规格

日期：2026-09-09  
项目工作名：`poker-points-tutorial`  
目标发布形式：公开 GitHub 仓库与 GitHub Pages 静态网站

## 1. 产品目标

制作一套面向新手、由浅入深的中文德州扑克积分桌教程。读者不仅要记住术语和公式，还要能跟随一手牌的时间线，看见发牌、行动、底池变化与翻牌动画，并在关键节点先作判断、再阅读解释。

教程默认使用六人桌示例，同时覆盖五至八人桌的位置变化。所有站内规则、牌例和计算只使用“积分”和“BB”，不使用货币单位，也不讨论积分与任何外部价值之间的兑换关系。

成功标准：一位没有系统学习过德州扑克的读者，完成核心路径后能够独立完成一手牌、看懂常用术语、理解有效筹码与 SPR、计算听牌与底池赔率，并能在下注前说明下注目的以及被跟注或加注后自己赢哪些牌、输哪些牌。

## 2. 固定牌局规则

- 参与人数：最少 5 人，最多 8 人，默认示例为 6 人。
- 盲注：小盲 10 积分，大盲 20 积分。
- 基准筹码：100BB = 2000 积分。
- 补充积分：只能在两手牌之间进行。
- 桌上积分：牌局进行期间不得主动减少或撤回已经在桌上的积分，避免领先玩家通过中途减少积分破坏深筹决策与桌面公平。
- 教程重点：既包括自己持有深筹的情况，也包括对手持有深筹的情况；所有决策优先使用双方较小者，即有效筹码。
- 范围边界：教程解释桌内规则与牌局决策，不涉及桌外结算。

站内对用户统一称“积分桌”。“现金桌”只作为项目需求背景，不出现在正式课程正文。

## 3. 教学原则

### 3.1 一手牌驱动一个概念

每个重要概念先从具体牌例进入：读者看见位置、底牌、有效筹码和行动，再由动画逐街揭示信息。理论解释紧跟牌例，避免把牌型、数学和策略拆成互不相干的词条。

页面的基本节奏为：

1. 展示局面与当前问题。
2. 让读者预测行动或数字。
3. 播放下一步动画。
4. 解释桌上可用的快速判断。
5. 展开精确计算或范围分析。
6. 用一道变体题检验迁移能力。

### 3.2 “下注必须有价值”贯穿全站

“找爹”不是章节名，也不作为正式术语。它代表一种常见思维错误：玩家因为自己绝对牌力看起来很强就下注，却没有分析更差的牌是否会跟注、更好的牌是否会弃牌，例如两对在强烈代表三条的范围面前持续做大底池。

所有涉及下注的章节和练习统一插入四问检查：

1. 这次下注是为了让更差的牌跟注，还是让更好的牌弃牌？
2. 如果是价值下注，具体有哪些更差的牌会跟注？
3. 如果是诈唬，具体有哪些更好的牌会弃牌？
4. 被跟注或加注以后，我仍然赢什么，又输给什么？

### 3.3 桌上捷径与课后精算并存

底池赔率、outs 和胜率先给桌上可执行的近似法，再解释精确公式。读者要知道近似法何时够用，也要知道它偏差来自哪里。

## 4. 课程信息架构

### 第一阶段：先完成一手牌

1. **欢迎与积分桌规则**：人数、盲注、100BB、局间补充积分和桌上积分限制。
2. **三分钟完整牌局**：从按钮位、盲注、底牌到河牌和摊牌，建立全局心智模型。
3. **牌型与比较**：高牌至皇家同花顺；处理公共牌参与、踢脚和相同牌型比较。
4. **座位与行动顺序**：六人桌为主，附五至八人桌位置对照。
5. **筹码、底池与有效筹码**：区分自己的筹码、对手筹码和真正可争夺的有效筹码。
6. **术语表**：中英文对照，可从正文术语悬浮卡片跳转。

### 第二阶段：翻前建立秩序

7. **起手牌记法**：对子、同花、非同花以及 `AKs`、`AQo` 等记法。
8. **位置与范围**：为什么越晚行动可以参与更多牌；用 13×13 范围矩阵互动展示。
9. **翻前行动与尺度**：弃牌、跟注、加注、再加注；所有尺度使用积分和 BB 双表示。

### 第三阶段：翻后先问“为什么”

10. **第一个翻后决策框架**：牌力、范围、牌面结构、位置、有效筹码和人数。
11. **下注目的**：价值、诈唬、保护与权益实现；四问检查在此首次完整出现。
12. **下注尺度与后续街计划**：下注前预想被跟注和被加注后的行动。
13. **多人底池**：范围更强、诈唬成功率下降、相对强牌更易受压。

常见错误不另建“错误大全”，而是在最相关的章节内以“误区—为什么—如何改”出现。

### 第四阶段：把数学变成桌上工具

14. **听牌与 outs**：识别干净 outs、受污染 outs 和重复计算。
15. **胜率与二四法则**：翻牌后两张牌约为 outs×4，只看下一张牌约为 outs×2；同时展示精确概率。
16. **底池赔率**：定义 `P` 为对手下注后、自己行动前的当前底池，跟注额为 `C`，所需最低胜率为 `C ÷ (P + C)`。例如当前底池 300、跟注 100，门槛为 25%。
17. **隐含赔率与反向隐含赔率**：后续可能获得更多积分，以及击中后仍可能落后的风险。
18. **SPR**：翻牌开始时有效筹码除以翻牌底池；解释 SPR 如何影响一对、两对和听牌的投入意愿。

### 第五阶段：深筹决策

19. **100BB、150BB、200BB 对比**：同一底牌和牌面，在不同有效筹码下比较尺度与承诺程度。
20. **有效筹码实验室**：分别调整自己和对手筹码，强调只增加单方筹码不会自动改变该对局的有效深度。
21. **深筹风险**：位置价值上升、坚果优势更重要、反向隐含赔率放大；重点处理“一对或两对看起来强，但只能被更强范围继续”的局面。

### 第六阶段：练习与查阅

22. **练习实验室**：按翻前、翻后、数学、深筹筛选题目，逐步提示而非只给结论。
23. **速查页**：牌型、位置、常见尺度、二四法则、底池赔率和四问检查。
24. **资源页**：英文频道、课程和工具链接，标明适合阶段、内容风格与是否需要注册。
25. **来源页**：列出规则、数学、技术和素材来源，区分引用、改写与项目自制内容。

## 5. 页面与导航

桌面端采用左侧课程导航、中央正文、右侧当前牌例或本节速查提示的阅读结构。动画主课可扩展为沉浸式宽屏牌桌。移动端按“正文—牌桌—解释—操作”的顺序纵向排列，关键牌面保持大字角标可读。

顶部仅保留课程进度、术语搜索、资源和浅色/深色切换，不增加社区、账号或排行榜。无需后端，也不要求登录。

推荐路由分组：`/start/`、`/preflop/`、`/postflop/`、`/math/`、`/deep/`、`/practice/`、`/reference/`。

## 6. 技术架构

### 6.1 框架选择

使用 **VitePress + Vue 3 + TypeScript**。VitePress 负责 Markdown 内容、导航、搜索和静态构建；Vue 组件直接嵌入课程页面，承担牌桌动画与计算实验。

选择它而不是 MkDocs 的原因：

- 课程本质仍是文档，VitePress 保留低成本 Markdown 写作流程。
- Vue 组件可以直接在 Markdown 中使用，复杂互动不需要以额外脚本注入文档。
- 官方提供静态部署与 GitHub Pages 工作流指引。
- 自定义主题足以实现编辑式教程外观，同时不重造路由、目录和搜索。

不引入 Nuxt、数据库、账号系统或服务端渲染。当前需求不需要这些复杂度。

### 6.2 模块边界

- `site/`：VitePress 课程 Markdown 与站点配置，只负责叙事、例题和组件参数。
- `src/components/cards/`：`PlayingCard` 与 `CardBack`，统一封装 SVGCards 路径、尺寸和无障碍文本。
- `src/components/table/`：牌桌布局、座位、底池、筹码与行动高亮。
- `src/components/timeline/`：牌局状态机，控制发牌、翻前、翻牌、转牌、河牌与暂停。
- `src/components/labs/`：赔率、outs、范围和深筹实验工具。
- `src/components/quiz/`：问题、提示、答案和本地进度。
- `src/data/hands/`：牌例数据；内容页不手写筹码变化逻辑。
- `src/lib/poker-math/`：赔率、outs、有效筹码、SPR 等纯函数。
- `src/theme/`：视觉变量、VitePress 主题扩展和页面布局。
- `docs/superpowers/`：设计与实施记录，不参与网站构建。

每个组件只依赖明确的数据输入；数学计算不写进展示组件，动画状态不写进课程 Markdown。

### 6.3 牌例数据流

每个牌例由 TypeScript 数据对象描述：人数、座位、起始积分、盲注、底牌、公共牌、逐步行动、教学暂停点和解释。`HandTimeline` 验证并按顺序消费行动，计算新的底池与筹码状态，再把同一状态传给 `PokerTable`、`ActionReplay` 和讲解面板。

所有积分使用整数保存。BB 只在显示层通过大盲 20 积分换算，避免两个数值源互相矛盾。非法行动、负筹码或底池不守恒在开发环境直接报错；生产页面显示“牌例数据有误”而不是继续播放错误动画。

## 7. 动态组件

- **PokerTable**：支持 5–8 座位，默认六人桌；显示按钮位、盲注、玩家积分、有效筹码和当前行动者。
- **PlayingCard**：使用本地 SVGCards 牌面；提供牌面、牌背、正反状态和教学用大尺寸模式。
- **HandTimeline**：播放、暂停、单步、重新演示；公共牌按实际节奏翻开。
- **ActionReplay**：按时间线显示弃牌、跟注、加注及底池变化。
- **RangeGrid**：13×13 起手牌矩阵，可按位置高亮范围并显示记法。
- **OutsExplorer**：读者点击可能改进手牌的牌，系统提示干净或受污染 outs。
- **PotOddsLab**：拖动底池与跟注额，实时显示比例、最低胜率和一步计算。
- **DeepStackLab**：分别调整双方筹码，比较有效筹码、SPR 与后续街可用尺度。
- **DecisionQuiz**：先选择行动和理由，再展开“赢什么、输什么”与四问检查。

交互进度只写入 `localStorage`。清除浏览器数据后进度可以丢失，这是静态、免登录方案的明确取舍。

## 8. 动画与视觉系统

正式牌面采用 [SVGCards](https://github.com/saulspatz/SVGCards) 的 Vertical2 大字角标牌组和蓝色牌背。全部 SVG 作为项目本地资源保存，不在正式网站运行时请求第三方图床，并在来源页保留公共领域说明。

动画只服务于信息变化：

- 发牌从牌堆移动到座位。
- 弃牌降低座位与牌背强调。
- 筹码移动与底池数字同步。
- 翻牌三张依次落下并翻面，转牌和河牌单张翻开。
- 教学暂停点停止自动播放，等待读者选择或继续。

动画主要使用 CSS transform 和 opacity，由状态机控制阶段。提供重新播放、暂停和单步；系统开启 `prefers-reduced-motion` 时取消位移动画，改为即时状态切换与轻微淡入。

视觉方向是“编辑式纸面教材遇见线下牌桌”：米白纸张、深绿绒布、墨色正文、黄铜强调和克制的红色。正文使用中文宋体风格，界面数字与控制使用系统无衬线体。避免常见 SaaS 卡片网格和无意义装饰动画。

## 9. 内容与措辞约束

- 正式页面只能出现积分与 BB；禁止货币符号、货币单位及兑换描述。
- 所有牌例给出人数、位置、有效筹码和当前底池，避免脱离上下文的结论。
- 策略描述区分“新手默认线”和“取决于范围的进阶讨论”，不把单一答案写成普遍定律。
- “找爹”不作为菜单、标题或正式术语；其思维内核通过四问检查和“赢什么、输什么”反复出现。
- 外部资源页可链接英文内容，但站内介绍仍遵守积分措辞，不复刻外部视频或课程的大段内容。

### 9.1 站点声音：“桌边教练”

文字像一位坐在读者旁边、愿意暂停牌局解释的教练：直接、克制、有现场感，但不装腔，也不故意耍俏。

- 先给局面或问题，再给定义。优先写“你在按钮位拿到 A♠J♠”，少写“本节将深入探讨”。
- 一个自然段只推进一个判断。能用两句说清楚，不扩成五句。
- 术语第一次出现时就地解释，之后使用统一名称；不连续堆叠多个新概念。
- 多问具体问题：“哪些更差的牌会跟？”少用空泛提醒：“需要综合考虑多种因素。”
- 结论要有边界。写“这是新手默认线”，不写“永远应该”。
- 避免“首先、其次、最后”“值得注意的是”“综上所述”“让我们深入探讨”等模板化衔接。
- 保留适量短句和停顿，让关键判断像牌桌口令一样醒目；不用密集感叹号、网络黑话或夸张比喻。

每章完成后进行一次人工朗读检查：删掉不影响含义的句子，确认开头 150 字内出现具体牌局或明确问题，并检查读者是否能复述本章唯一的核心判断。

## 11. 可访问性与降级

- 所有牌面具有可读文本，如“黑桃 A”，不只依赖图像。
- 花色同时使用形状与颜色；红绿色差异不是唯一提示。
- 播放控件支持键盘和清晰焦点状态。
- 讲解文本不因动画播放而消失；暂停后可完整阅读。
- JavaScript 未加载时仍可阅读课程正文、公式和静态牌例截图。
- SVG 加载失败时显示牌名占位，避免出现空白牌位。
- 外链使用常规链接，不要求弹窗；失效链接由构建检查报告。

## 12. 测试策略

- **Vitest 单元测试**：有效筹码、底池守恒、BB 换算、SPR、底池赔率、outs 精确概率。
- **Vue 组件测试**：牌面状态、时间线单步、暂停/重放和错误态。
- **Playwright 浏览器测试**：桌面与移动端完成一手动画；键盘操作；减少动态效果；练习反馈；本地进度恢复。
- **内容测试**：扫描正式课程目录，阻止货币符号、货币单位和禁用措辞进入构建；检查每个牌例是否声明人数、位置、盲注与有效筹码。
- **构建与链接测试**：VitePress 完整构建、内部链接、静态资源和资源页外链检查。
- **视觉检查**：关键页面截图覆盖 6 人桌、5/8 人布局、手机宽度和深色模式。

## 13. GitHub 与发布

仓库工作名为 `poker-points-tutorial`，默认创建为公开仓库。`main` 分支是发布源：推送后由 GitHub Actions 安装依赖、运行测试、执行 VitePress 构建、上传静态产物并部署到 GitHub Pages。

VitePress 的 `base` 根据最终仓库名生成，避免项目 Pages 子路径下资源失效。部署前先在本地以生产模式预览，再验证线上首页、深层路由、刷新、牌面资源和动画。

最终交付包括：

1. 桌面文件夹“德州扑克积分桌入门”，包含完整 Git 仓库。
2. GitHub 公开仓库地址。
3. GitHub Pages 公开访问地址。
4. README，说明本地开发、构建、测试、内容规范与来源。

## 15. 实施分段

开发按可独立验证的纵向切片推进，但最终交付包含全部切片：

1. **站点底座**：VitePress、主题、导航、本地 SVGCards、内容措辞检查与 GitHub Pages 基础配置。
2. **新手闭环**：前六页、完整一手牌、`PokerTable`、`PlayingCard`、`HandTimeline` 与 `ActionReplay`。这一阶段先证明读者可以从零完成一手牌。
3. **决策闭环**：翻前和翻后章节、`RangeGrid`、下注四问与多人底池牌例。
4. **数学与深筹闭环**：outs、胜率、底池赔率、SPR、100/150/200BB 对比及三个互动实验室。
5. **学习闭环与发布**：练习、速查、术语、资源、来源、全站无障碍与视觉检查，最后推送 GitHub 并部署 Pages。

每个切片都要先通过对应测试再进入下一段。某个切片可供预览不代表项目完成；只有第五段上线且桌面副本同步后才完成交付。

## 16. 完成定义

满足以下条件才视为完成：核心 25 页均有可读正文；至少一手完整五街动画；主要数学概念均有互动实验；100BB、150BB、200BB 深筹对比可操作；所有站内牌例只使用积分与 BB；桌面和手机端通过可访问性与交互测试；SVGCards 全部本地化；GitHub Actions 通过；GitHub Pages 可公开访问；桌面文件夹与远程仓库保持同一提交。
